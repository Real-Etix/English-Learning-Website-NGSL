# Reviewed meanings with limited examples

The user approved publishing appropriate, factual meanings without requiring an example, and allowing meaning-based claims. Example-dependent practice must remain unavailable. This is a local content release, not deployment authorization.

## Publication contract

- The existing sourced-example publication path remains unchanged.
- An explicit per-sense `meaningReview` receipt permits the limited-example exception. It records a date, rationale, policy version, and exact content snapshot (not a security signature). The snapshot binds the word identity, display, editorial scope, and sense content including attribution. Changing reviewed text or sources invalidates it.
- Factual, attributable definition evidence is still mandatory. A receipt does not make AI text factual, publish draft senses, bypass archives, or approve relationships.
- Only individually reviewed senses in an explicit, record-hash-pinned release manifest are promoted. Unselected uncertain senses stay hidden without deleting their text. Official core records and archived specialists are not changed.
- A claim quiz uses the definition when no example exists. With too few distractors, it asks for the word rather than offering a one-option answer.
- The word card identifies limited examples. Composition and solidification require an example for these newly reviewed senses, on both client and server. The tutor receives the limitation.

## Scope and verification

Do not bulk-approve the remaining hidden corpus. No new paid calls, no subagents, no deployment, no automatic connection promotion.
